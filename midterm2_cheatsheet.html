Which byte do I write in binary? The byte where the mask ends: /9–/16 is byte 2, /17–/24 is byte 3, /25–/32 is byte 4. Bytes before it are copied unchanged. The value of the byte does not matter.

Counting trick: the 3rd byte goes up by 1 for every 256 addresses (512 addresses = 2 steps of the 3rd byte, 1024 = 4 steps).

C. NETWORK ADDRESS, RANGE, HOSTS

How:
  1. Find the byte where the mask ends and its block size (table A).
  2. Network address: in that byte, go down to the nearest multiple of the block size (same as host AND mask). Later bytes become 0.
  3. Last address (broadcast): that byte + block size − 1. Later bytes become 255.
  4. Hosts are everything between: first + 1 up to last − 1. Number of hosts = addresses − 2.

D. SUBNETS OF EQUAL SIZE

How:
  1. Check it fits: number of subnets × size must be ≤ addresses in the lease.
  2. New mask from the subnet size (table A).
  3. Subnets start at the lease address and go up by the subnet size.
  4. The k-th subnet starts at: lease start + (k − 1) × size. (The 1st subnet is the lease start itself.)
Example (HW5 Q4): lease 194.23.56.128/25, three subnets of 32 addresses. Host addresses?
Fits? /25 has 128 addresses, need 3 × 32 = 96. Yes.
32 addresses = 2^5, so the mask is /27.
Start at .128 and add 32 each time:
  subnet 1: .128 to .159   hosts .129 to .158
  subnet 2: .160 to .191   hosts .161 to .190
  subnet 3: .192 to .223   hosts .193 to .222
  (.224 to .255 is left over)
Example (HW5 Q5): 128.17.144.0/22 in subnets of 32. The 20th subnet?
32 addresses, so /27. Start + (20 − 1) × 32 = start + 608.
608 = 2 × 256 + 96, so byte 3 goes up by 2 and byte 4 is 96:
  144 + 2 = 146, byte 4 = 96.
Range: 96 to 96 + 31 = 127.
128.17.146.96/27, range 128.17.146.96 to 128.17.146.127

Total hosts when /20 is cut into /27s: number of subnets 227−20 = 128, hosts in each 25 − 2 = 30, total 128 × 30 = 3840.

E. SUB-BLOCKS OF DIFFERENT SIZES

How:
  1. Round each request up to a power of 2 and find its mask (table A).
  2. Check the total fits in the block.
  3. Place the largest first, then the next largest, each one starting right after the previous one ends.
  4. What is left over is the reserve.
Largest first keeps every block on a legal starting point (a multiple of its own size) with no gaps.
Example (Prof Ex1): 129.249.64.0/20, sub-blocks of 32, 512 and 128 addresses.
/20 has 4096 addresses: 64.0 to 79.255. Need 672. Fits.
512 first (/23): 512 = 2 steps of byte 3, so 64.0 to 65.255
128 next (/25):  starts at 66.0, ends at 66.127
32 last  (/27):  starts at 66.128, ends at 66.159
Left over: 4096 − 672 = 3424 addresses, from 66.160.
512: 129.249.64.0/23 · 128: 129.249.66.0/25 · 32: 129.249.66.128/27
Example (5.35, groups): ISP 190.100.0.0/16. Group 1: 64 customers × 256. Group 2: 128 × 128. Group 3: 128 × 64.
Size of each group = customers × addresses:
  G1 = 16384 (/18), 16384/256 = 64 steps: 0.0 to 63.255

  G3 = 8192 (/19), 32 steps:              128.0 to 159.255

F. CIDR (JOINING NETWORKS)

How:
  1. Find the first byte where the addresses differ. Write it in binary for each address.
  2. Count how many bits from the left are the same in all of them.
  3. Prefix = bits in the earlier bytes (8, 16 or 24) + that count.
  4. Address: keep the common bits, set every later bit to 0.
Example (HW5 Q3): 18.198.34.192/30, 18.198.34.240/30, 18.198.33.252/30
Bytes 1 and 2 are equal. Byte 3:
  34 = 0010 00|10
  33 = 0010 00|01     6 bits are the same
Prefix = 16 + 6 = 22. Common bits then zeros: 0010 0000 = 32.
18.198.32.0/22

Why CIDR: one table entry can stand for many networks (route aggregation), and addresses are not wasted in fixed class sizes.

G. WRITING A FORWARDING TABLE

How: columns are DST | Mask | Next Hop | Interface.
  1. Networks plugged directly into this router: Next Hop is "–", Interface is the port they are on.
  2. Every other network: ask "which neighbour router is it behind?" Next Hop is that neighbour's address on the link we share. Interface is my port toward that neighbour.
  3. If the Internet (or everything that is left) is behind one neighbour, write one default row: 0.0.0.0 /0.
  4. Order the rows from the longest mask to the shortest.
Check every row: next hop is never my own address · "–" only for networks plugged into me · interface = my port toward that neighbour · default mask is /0 (not /32) · number of rows = my networks + far networks (or one default).
Example (Prof practice, router Rx):

H. WHICH ROW DOES A PACKET USE?

How (range method, no binary):
  1. Turn every row into a range: block size from table A; range = start to start + block − 1 (in the byte where the mask ends).
  2. Mark the rows whose range contains the destination.
  3. Several marked: use the longest mask. None marked: use the default row (0.0.0.0/0). No default: dropped.
Example: 20.16.0.0/12 → A, 20.24.0.0/13 → B, 20.28.0.0/14 → C, 0.0.0.0/0 → D
/12: 4 mask bits in byte 2, block 16:  20.16 to 20.31  (A)
/13: 5 mask bits in byte 2, block 8:   20.24 to 20.31  (B)
/14: 6 mask bits in byte 2, block 4:   20.28 to 20.31  (C)
To 20.27.5.5: in A yes, in B yes, in C no. Longest is /13: B
To 20.32.1.1: in none of them. Default row: D
To 20.29.0.1: in A, B and C. Longest is /14: C

Jeopardy: a.b.c.0/24 against a.b.c.d/26: the /26 wins (longest prefix). Routing table: cost and several options. Forwarding table: no cost, one option.

I. IP HEADER

Default header: 12 fields, 20 bytes.

Version (4 bits)4 for IPv4
Hlen (4)header length counted in 4-byte words: 5 means 20 bytes, 6 means 24
TOS (8)type of service
Length (16)total bytes, header + data
Ident (16)same number in all fragments of one datagram
Flags (3)0, DF = do not fragment, MF = more fragments
Offset (13)where this fragment's data starts, counted in units of 8 bytes
TTL (8)minus 1 at every router; dropped at 0
Protocol (8)which transport protocol: TCP = 6, UDP = 17
Checksum (16)of the header only
Source, Destination32 bits each
Optionsoptional: source route, record route

Data carried = Length − header bytes. Example: Hlen 6, Length 1500: header 24, data 1476.

J. FRAGMENTATION

How:
  1. Data to send = Length − 20.
  2. Biggest data per fragment = MTU − 20, then round down to a multiple of 8.
  3. Cut the data into pieces of that size. The last piece is whatever is left.
  4. For each fragment: Length = its data + 20. Offset = (data bytes that came before it) ÷ 8. MF = 1, except the last fragment where MF = 0.
Example (Jeopardy): MTU = 61, Length = 100. Offset of the 2nd fragment?
Data = 100 − 20 = 80 bytes.
Per fragment: 61 − 20 = 41, rounded down to 40.
Fragment 1 carries bytes 0–39.   Offset 0,          MF 1
Fragment 2 carries bytes 40–79.  Offset 40 ÷ 8 = 5, MF 0
Fragment offset = 5
Example: Length = 4000, MTU = 1500.
Data = 3980. Per fragment: 1480 (already a multiple of 8).
  Fragment   Data   Length   Offset          MF
  1          1480   1500     0               1
  2          1480   1500     1480 ÷ 8 = 185  1
  3          1020   1040     2960 ÷ 8 = 370  0

Watch out: MTU 310 gives 290, which must be rounded down to 288. If DF = 1 and the datagram is too big, the router drops it.

K. FACTS FOR VERBAL QUESTIONS

  • IP is connectionless and best effort: packets can be lost, reordered, duplicated or delayed.
  • Routers fragment. Only the destination host reassembles.
  • Next hop is always the neighbour's address, never my own.
  • A network address (host bits all 0) cannot be a destination host.
  • Subnets are visible only inside the site.
  • MTU: Ethernet 1500 bytes, FDDI 4500 bytes.
  • All fragments carry the same Ident; a lost fragment means the whole datagram is lost.
  • CIDR prefixes can be any length; every router must understand them.
  • Flags field: 0, do not fragment, more fragments. Options: source route or record route.
  • Default IP header: 12 fields, 20 bytes. Protocol field: transport protocol, like UDP or TCP.
  • A host has one default router; a router has a forwarding table.
  • Overlapping prefixes are allowed; the longest match is used.
