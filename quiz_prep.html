Part I — Important Topics (from the slides)

1. Layered model (Internet / TCP/IP)

  • TCP/IP has 4 layers (per slides): Application, Transport, Network, (Data) Link. Hosts implement all 4; routers only the bottom two (Network + Link).
  • OSI has 7 layers: Application, Presentation, Session, Transport, Network, Data Link, Physical.
  • Reasons for layering: divide network operation into less complex elements; standard interfaces for plug-and-play / multi-vendor; modular development.
  • A structured set of protocols = communications architecture or protocol suite. Protocols are independent, each does one task, grouped in a hierarchy.

  • network = connected communicating devices; internet = two or more networks that communicate; the Internet = the most notable one (since 1969). ISP = Internet Service Provider, NAP = Network Access Point.

2. Protocols & standards

  • Protocol = rule(s); strict adherence. Standard = agreed-upon rules, established by authority, custom or general consent; developed by committees, forums, government/regulatory agencies.
  • Internet standard = thoroughly tested specification. Starts as an Internet Draft (no official status, six-month lifetime) → may be published as an RFC (Request for Comment).
  • RFC maturity levels: Proposed standard → Draft standard → Internet standard; plus Historic, Experimental, Informational.
  • RFC requirement levels: Required, Recommended, Elective, Limited use, Not recommended.
  • Internet administration: ISOC (Internet Society), IAB (Architecture Board), IETF (Engineering Task Force), IESG (Eng. Steering Group), IRTF (Research Task Force), IANA (Assigned Numbers Authority), ICANN, NIC (Network Information Center).

4. Links

  • Shannon–Hartley: C = B · log2(1 + S/N) bps. dB = 10 · log10(S/N) → 30 dB means S/N = 1000. Example (slide): B = 3300 − 300 = 3000 Hz, 30 dB → C ≈ 30 kbps.
  • Wavelength = speed / frequency. On copper, speed ≈ 2/3 · 3×108 m/s. Slide: 300 Hz on copper → 2×108/300 ≈ 667 km.
  • Media: copper (DSL, coax), optical fiber, free space (wireless). Encoding = placing binary data on a signal; modulation = modifying frequency, amplitude, phase.

5. Encoding

  • NRZ: 1 = high, 0 = low. Problems: baseline wander (long runs change the receiver's average) and clock recovery (no transitions → lose sync).
  • NRZI: transition to encode 1, stay to encode 0. Solves consecutive 1s, not consecutive 0s.
  • Manchester (slides' convention): XOR of NRZ data and the clock. 0 = low→high, 1 = high→low (mid-bit). Problem: doubles transitions → bit rate = half the baud rate (50% efficient).
  • 4B/5B: every 4 data bits → 5-bit code; no more than one leading 0 and two trailing 0s → never more than three consecutive 0s. Sent with NRZI. 80% efficient. Examples: 0000→11110, 0001→01001, 0010→10100, 1111→11101. 11111 = idle, 00000 = dead, 00100 = halt. Of 16 unused codes: 7 invalid, 6 control.

6. Framing

  • Frames (blocks of data) are exchanged between nodes; the adaptor must recognize where a frame begins and ends.
  • Byte-oriented protocols: BISYNC (IBM, late 1960s), DDCMP (DECNet).
  • BISYNC sentinel approach: SYN (synchronize), SOH (start of header), STX (start of text), ETX (end of text), DLE (data link escape — character stuffing), CRC.

7. Error detection — overview

  • Bit errors come from electrical interference and thermal noise. On error: (1) notify sender → retransmit, or (2) correct it at the receiver.
  • Idea: add redundant bits (no new information, derived by an algorithm both sides know). Receiver recomputes r from m; match → no error.
  • Sending two full copies = poor scheme (n redundant bits, errors can still go undetected). Good schemes: k redundant bits, k ≪ n. Ethernet: up to 12,000 bits protected by a 32-bit CRC.
  • Where used: CRC → HDLC, DDCMP, CSMA/CD, Token Ring · 2-D parity → BISYNC · Checksum → IP (not at link level).

8. Single (1-D) parity

  • Add one bit to a 7-bit code (8th bit). Even parity: total number of 1s even. Odd parity: total number of 1s odd.
  • Detects any odd number of bit errors; misses every even number (each flip changes the count by ±1, so an even number of flips keeps even/odd the same).
  • Number of k-bit error patterns in an n-bit word (n includes P) = C(n,k).

9. Two-dimensional parity

  • Parity bit for each byte (row) plus a parity byte for each bit position across all bytes (column).
  • Catches all 1-, 2-, 3-bit errors and most 4-bit errors. Misses 4 errors on the corners of a rectangle. Can locate and correct a single-bit error (failing row × failing column).
  • With odd parity and an odd×even block, the corner bit computed from the row vs. column differs — state which you used.

10. Internet checksum

  • Treat data as 16-bit integers; add with ones-complement arithmetic (carry out of the MSB is added back to the result); checksum = ones complement of the sum.
  • Ones complement: −x = invert every bit of x. Slide example (4-bit): −5 = 1010, −3 = 1100; 1010 + 1100 = 1 0110 → 0110 + 1 = 0111 = −8.
  • Receiver adds everything including the checksum; complement = 0 → OK.

11. CRC (Cyclic Redundancy Check)

  • Bit string ↔ polynomial: 110001 = x5 + x4 + 1 (degree 5). A k-bit frame has max degree k−1.
  • M(x) = message, C(x) = generator of degree r. Only C(x) must be known by both sides.
  • Steps: append r zeros (xrM(x)) → divide by C(x) with modulo-2 (XOR) division → subtract (XOR) the remainder (≤ r bits) → transmit. Receiver divides; remainder ≠ 0 → error.
  • Received = P(x) + E(x). Error undetected only if C(x) divides E(x).
  • Detects: all single-bit errors (if xk and x0 terms nonzero); all double-bit errors (if C(x) has a factor with ≥ 3 terms); any odd number of errors (if C(x) contains factor (x+1)); any burst shorter than k bits.
  • Standards: CRC-8 = x8+x2+x+1, CRC-10, CRC-12, CRC-16 = x16+x15+x2+1, CRC-CCITT = x16+x12+x5+1, CRC-32.
  • Corrupt frames are discarded; reliability is recovered with acknowledgements and timeouts.
